# M2.2 — control plane + gateway + Android E2E

M2.2 turns the existing development pieces into a repeatable end-to-end path.

## 1. Gateway agent

On the Linux host that owns `tunnelpilot0`:

```fish
export TUNNELPILOT_GATEWAY_AGENT_TOKEN="$(openssl rand -hex 32)"
export TUNNELPILOT_WG_INTERFACE=tunnelpilot0
export TUNNELPILOT_WG_MAX_PEERS=240
uvicorn server.gateway_agent.app:app --host 127.0.0.1 --port 8787
```

The agent's `/healthz` endpoint now reports WireGuard availability, current peer count and remaining peer capacity.

## 2. Control plane

Run the control plane with the gateway endpoint and real public server identity:

```fish
set -x TUNNELPILOT_GATEWAY_AGENT_URL http://127.0.0.1:8787
set -x TUNNELPILOT_GATEWAY_AGENT_TOKEN $TUNNELPILOT_GATEWAY_AGENT_TOKEN
set -x TUNNELPILOT_SERVER_ID dev-lan-1
set -x TUNNELPILOT_SERVER_REGION dev-lan
set -x TUNNELPILOT_SERVER_HOSTNAME 192.168.1.85
set -x TUNNELPILOT_SERVER_PORT 51820
set -x TUNNELPILOT_SERVER_PUBLIC_KEY (sudo cat /etc/wireguard/tunnelpilot0-server_public.key)
set -x TUNNELPILOT_VPN_GATEWAY_ADDRESS 10.67.0.1
uvicorn server.app.main:app --host 0.0.0.0 --port 8000
```

Replace `192.168.1.85` with the LAN address that the Android device can reach. Never put the gateway private key or the gateway-agent token into Git.

## 3. Check the catalog

From a host that can reach the control plane:

```fish
curl http://127.0.0.1:8000/v1/servers | python3 -m json.tool
```

The server should report a healthy gateway, for example:

```text
health_status: ok
wireguard_available: true
peer_count: 0
capacity_remaining: 240
```

## 4. Run the smoke test

Generate a throwaway WireGuard public key on a trusted machine, then:

```fish
set -x DEVICE_ID tunnelpilot-m22-test
set -x CLIENT_PUBLIC_KEY '...'
./infra/smoke/m2-control-plane-gateway.sh
```

The script verifies that the control plane can see the gateway and that device registration causes the gateway agent to provision a `/32` peer.

The test is idempotent for the same device id + public key. Use `CLEANUP=1` to revoke it after the check.

## 5. Android

In TunnelPilot:

1. Open `Setup`.
2. Set `Control plane URL` to the LAN address of the control plane, for example `http://192.168.1.85:8000`.
3. Tap `Provision device`.
4. Open `VPN` and connect.

The Android client generates its own private key, sends only the public key to the control plane, receives the allocated `/32` and gateway public routing data, and stores the resulting WireGuard config encrypted locally.

Verify on the gateway:

```fish
sudo wg show tunnelpilot0
```

A successful connection should produce a fresh handshake and increasing RX/TX counters.

## 6. Routing mode test

After All apps mode works, select one ordinary app under `Apps`, switch to `Selected apps`, and press `Reconnect with new routing`.

M2.2 now serializes VPN operations and waits for the WireGuard backend to reach the expected state before reconnecting, avoiding the previous disconnect/reconnect race.
